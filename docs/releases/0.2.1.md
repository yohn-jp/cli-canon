# CLI Canon 0.2.1

## Summary

0.2.1 completes three generic CLI contracts needed by consumers migrating onto the Canon-owned shell and composed command model:

- required-value options can now opt into fail-closed `optionLookingValuePolicy: "reject"` semantics;
- delegated commands can receive declared `placement: "anywhere"` fields before their route without consumer-side argv rewriting;
- public commands can declare presentation-only `prominence: "primary" | "advanced"` for progressive human help.

These changes are additive to the 0.2.0 public model. Existing declarations retain their previous defaults: required option values continue to use `"consume"` unless `"reject"` is requested, and commands with no prominence remain `"primary"`.

Normative architecture remains [`docs/architecture/CANON.md`](../architecture/CANON.md). These notes describe the consumer-visible release delta.

## Fail-closed option-looking values

Required-value options may declare:

```ts
option("--repository", z.string(), {
  optionLookingValuePolicy: "reject",
});
```

With `"reject"`, a separately spelled option-looking token is not consumed as the required value. Canon reports the existing structured `missing-option-value` usage failure and leaves the following token available to normal shell and grammar resolution.

This is particularly important for standard shell tokens:

- `--repository --help` preserves Help precedence;
- `--repository --json` preserves machine presentation while reporting the missing repository value;
- attached values such as `--repository=--value` remain explicit values;
- the existing negative-number lexical exception is unchanged, so values such as `-1` remain value-looking rather than option-looking.

The default `"consume"` policy is unchanged.

## Delegated anywhere fields

Composed delegated command sources may now declare options or flags with `placement: "anywhere"` and receive them before the delegated route.

For example, a delegated command that owns `--profile` can accept both:

```text
tool --profile prod assets sync
tool assets sync --profile prod
```

Canon still resolves the composed route owner exactly once. Leading option occurrences are admitted from the composed field grammar, attributed only after route ownership is resolved, and forwarded only to an owner that declares them.

To keep that pre-route grammar deterministic:

- incompatible declarations for the same anywhere spelling fail construction with `FLAG_COLLISION`;
- delegated anywhere fields may not claim Canon-reserved shell tokens;
- a leading field not owned by the resolved command fails as `unknown-option`;
- Help, JSON presentation, version, unknown-command, and no-command behavior remain Canon-owned;
- there is no fallback dispatch to another source.

Consumers no longer need a route-first argv rewrite merely to move delegated anywhere fields behind a route.

## Progressive command help

Command declarations and delegated command descriptors may now declare:

```ts
prominence: "primary" | "advanced"
```

Prominence is presentation metadata only.

- Omitted prominence resolves to `"primary"`.
- Summary/default human Help lists public primary commands.
- Full Help includes public primary and advanced commands.
- Explicit Help for an advanced command remains available.
- Machine discovery retains advanced commands and exposes the resolved `prominence`.
- Public advanced commands remain executable and Skill-addressable.
- Existing `visibility: "public" | "private"` semantics are unchanged and remain independent from prominence.

Canon intentionally defines only the two generic presentation levels. Product-specific classifications remain consumer-owned.

## Compatibility

0.2.1 is intended as a backward-compatible patch over 0.2.0.

No existing default changes:

- `optionLookingValuePolicy` still defaults to `"consume"`;
- omitted command prominence behaves as `"primary"`;
- canonical-only route execution is unchanged;
- private-command and Skill visibility rules are unchanged.

The stricter composed behavior is limited to declarations that were ambiguous or invalid under the newly supported delegated-anywhere contract: conflicting anywhere grammars and delegated claims on reserved shell flags now fail deterministically instead of requiring or permitting consumer-side normalization.
