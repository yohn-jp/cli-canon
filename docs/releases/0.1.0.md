# CLI Canon 0.1.0

## Summary

0.1.0 is the initial public release of `@yohn-jp/cli-canon`, the shared
TypeScript CLI contract framework for yohn-jp products.

The release establishes the architecture-conformance baseline completed before
consumer adoption begins. It provides one typed authoring authority for command
syntax and derives runtime routing, progressive help, JSON discovery, typed
invocation, Skill projections, Path Canon, output policy, public schema
projection, and reusable source/built/packed certification from that authority.

CLI Canon deliberately does not absorb product-domain authorization,
state-machine decisions, provider behavior, filesystem safety, or transport
authority.

## Added

- Typed Command Canon with inferred Command IDs, input types, handler bindings,
  and result validation.
- Nested routes, required/optional positionals, flags, aliases, repeated
  options, required/optional-value options, `--name=value`,
  `placement: "anywhere"`, and trailing raw argv.
- Progressive root/domain/leaf text help, full help, and JSON discovery derived
  from the compiled command graph.
- Canonical structured invocation projection as
  `{ executable, argv: string[] }`, including typed Skill bindings and
  explicit `requires-input` states.
- Output/CliIO contracts that distinguish usage, validation, domain,
  handler-result, serialization, budget, and unexpected failures.
- Strict machine JSON behavior: complete documents only, UTF-8 byte budgets,
  no truncation, and explicit rejection of non-finite or unsupported values.
- Skill Canon with intent, invariants, prose steps, Command references,
  delegation, opaque domain-result references, visibility enforcement, and a
  default 4096-byte output budget.
- Path Canon with derived IDs, required parameters, file/directory kinds,
  parent references, explicit resolution context, and ordered root strategies.
- Package identity and JSON-safe public discovery projection.
- Complete vs structural-only JSON Schema projection, with explicit rejection
  when a declared complete projection is unsupported.
- `@yohn-jp/cli-canon/testing` with explicit certification scenarios for
  source, built, and packed execution lanes.
- Exact packed-artifact verification for exports, public types, root-import
  purity, and runtime behavior.

## Package surfaces

```text
@yohn-jp/cli-canon
@yohn-jp/cli-canon/node
@yohn-jp/cli-canon/testing
```

The root package is side-effect free. Commander remains private to the Node
adapter.

## Compatibility

This is the first published version, so there is no prior npm compatibility
contract to preserve.

Node.js 24 or newer is required. Zod 4 is a peer dependency.

## Known limitations

Two grammar forms are intentionally not admitted by the current Commander
backend:

1. Order-sensitive repeated option groups declared through
   `orderedOptionGroups`.
2. `optionLookingValuePolicy: "reject"`.

Both fail at construction with `UNSUPPORTED_GRAMMAR`; CLI Canon does not
silently emulate them with a second parser.

## Install

```bash
npm install @yohn-jp/cli-canon@0.1.0 zod
```

## Release verification

Before publishing 0.1.0:

```bash
pnpm install --frozen-lockfile
pnpm run verify
pnpm pack
node scripts/smoke-test.mjs --tarball ./yohn-jp-cli-canon-0.1.0.tgz
```

0.1.0 is the bootstrap release and is published manually to npm from the
verified tarball. After npm publication is confirmed, create GitHub Release
`v0.1.0` targeting the exact release commit.

The synchronized release workflow detects that 0.1.0 is already present on npm
and skips the publish action while still exercising the shared build/pack/smoke
path.

Starting with the next release, npm Trusted Publishing/OIDC is the canonical
publish path triggered by the GitHub Release.
